# ТОК — Android

Это Android-клиент сайта ТОК. Приложение открывает ту же веб-версию ТОК внутри WebView, поэтому авторизация, знакомства, мэтчи, чаты, профиль и Supabase работают через тот же backend.

## Открыть в Android Studio

Откройте папку `android/` как отдельный Android-проект.

Требования:
- Android Studio
- JDK 17
- Android SDK 35

URL сайта задаётся в:
`app/src/main/java/ru/tok/ispu/MainActivity.java`

Сейчас используется:
`https://tok-ispu.pages.dev/`

Если production-домен другой, поменяйте только `START_URL`.

## Важно

Это именно клиент сайта, а не отдельная копия backend. Изменения сайта автоматически появляются в приложении после обновления страницы/релиза, а данные остаются в общей базе Supabase.

## APK

Для проекта настроена автоматическая сборка APK через GitHub Actions. После изменений Android-проекта GitHub собирает APK и прикладывает его к релизу. Сборка запускается автоматически.

## Постоянная подпись APK (важно для обновлений)

APK должен подписываться одним и тем же ключом при каждом релизе. Иначе Android не сможет установить новый APK поверх предыдущего. Ключ не хранится в репозитории: он передаётся сборке через GitHub Actions Secrets.

1. Создайте закрытые Actions secrets в репозитории **Settings → Secrets and variables → Actions**:
   - `TOK_ANDROID_KEYSTORE_BASE64` — содержимое keystore в Base64;
   - `TOK_ANDROID_KEYSTORE_PASSWORD` — пароль хранилища;
   - `TOK_ANDROID_KEY_ALIAS` — alias ключа (для подготовленного ключа: `tok-release`);
   - `TOK_ANDROID_KEY_PASSWORD` — пароль ключа.

2. Чтобы получить Base64 из `tok-release.jks` в Windows PowerShell, выполните:
   ```powershell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes(".\tok-release.jks")) | Set-Clipboard
   ```
   Команда скопирует значение в буфер обмена. Вставьте его в secret `TOK_ANDROID_KEYSTORE_BASE64`. Не добавляйте сам файл или его содержимое в Git.

3. После сохранения секретов откройте **Actions → Build Android APK → Run workflow**. Сборка создаст подписанный APK и GitHub Release.

Старые APK выпускались с временными debug-подписями. Поскольку их закрытые ключи из временных CI-окружений недоступны, первый APK с постоянной подписью нельзя установить поверх старого. Один раз удалите старое приложение и установите новый подписанный APK. После этого следующие релизы смогут обновляться поверх установленной версии. Учётная запись и данные профиля в Supabase не удаляются, но локальную сессию потребуется открыть заново.
